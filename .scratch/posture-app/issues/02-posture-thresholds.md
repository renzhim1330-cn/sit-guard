# 不良坐姿判定阈值与校准

## Question

在轻量校准（孩子先坐好、点一下「这就是标准坐姿」）的前提下，三类不良坐姿的判定几何与阈值如何定？

- 用哪些关键点、什么角度 / 距离公式判定「驼背（躯干前倾）」「头过低」「侧倾」？
- 相对校准基准如何表达（角度偏差量？相对比例？——需考虑不同身高、摄像头摆放角度差异）？
- 各阈值初值定多少？3–5 秒宽限的时间常数放在判定链的哪一环？
- 换人、换摆放角度后的稳定性；孩子正常小动作（喝水、翻书、抬头）时的抗误报策略（移动平均 / 迟滞区间？）。

解析方式：`/prototype` 会话——用真实素材做粗糙阈值调试原型（「采集测试素材」票的视频可用时优先用），产出阈值初值与判定公式，记录到本文件 `## Answer`。

## Prototype（资产）

- 原型文件：`prototypes/02-posture-thresholds.html`——双击即开、无网络依赖、一次性（throwaway）
- 验证对象：判定层状态机（正常 / 疑似 / 超标 + 迟滞 + 宽限计时 + 提醒冷却，**无度量平滑**）；阈值均为初值，可在页内「阈值微调」改
- 未验证：`measure()` 关键点 → 度量的坐标约定（待票 05 素材或摄像头试跑）

## Answer

**判定模型（经原型验证，用户确认）：**

1. **校准与度量**：校准捕获当前姿态为基准；三个度量——驼背 = 髋→肩连线与竖直方向夹角；头过低 = 鼻相对肩中点高度 ÷ 躯干长（尺度无关）；侧倾 = 耳线、肩线相对水平倾角的较大者。所有阈值一律以「偏离校准基准」计（非绝对值）。
2. **判定链（无平滑）**：偏离 → 状态带（正常/疑似/超标）→ 超标持续宽限计时 → 提醒 → 冷却。**不对度量做 EMA 平滑**——平滑会让偏离值渐近逼近阈值、边界永远触发不了（原型实测 bug）；抗误报交给迟滞带 + 持续宽限计时。
3. **阈值初值（偏离量）**：驼背 疑似 8° / 超标 12° / 迟滞 2°；头过低 12% / 20% / 3%；侧倾 8° / 12° / 2°。宽限 3.5s（落在已定的 3–5s 区间）；提醒冷却 30s、同类连续 ≤2（最终值归票 04）。
4. **同时超标**：同一刻只发一条，相对阈值偏离最大者（d/t2）先发；其余宽限保持就绪，冷却结束后补发。
5. **坐正表扬**：离开「超标」带即发表扬事件（文案归票 04）。
6. **UX 教训**：界面只展示状态（正常/疑似/超标），孩子与家长无需看到角度数字；阈值永远以偏离量计。
7. **待验证**：`measure()` 的坐标约定需在真实数据（票 05 素材或摄像头）上确认一次。

原型资产：`prototypes/02-posture-thresholds.html`（一次性；其中判定引擎 `createEngine` 为纯模块，可直接搬入实现）。
